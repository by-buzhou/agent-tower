# AgentTower · 多路拆单与定稿施工图 SOP

在 `relay` 或 `complex` 模式下准备动手实现前，先按耦合度与交付边界分级；命中复杂单兵或多独立低耦合模块并派时，按本流程落地 `.agent-tower/plans/` 施工图并推进真并发开发。

## 1. 规模分级（按耦合度拆轨，禁止机械按文件数一刀切）

- **0 派直答（免写施工图）**：纯问答、纯文案/样式微调，或核心源码 `<= 4` 文件明确改动（顺带改断言的单测不计入拆单门槛），主会话直接改完并跑语法快检与关联定向单测收口。
- **单兵执行（1 路 `isolation: "shared"`）**：单领域强耦合改动（不论总文件数是否 `>= 6`，如前端 HTML+JS+CSS+配套单测），由 1 名已启用执行官（未点名时默认选 ★ 首选）同目录改完直接跑绿，**严禁把源码与单测、HTML/JS 与 CSS 硬劈成隔离 Worktree 盲写**；跨阶段边界复杂时可落一份简版 `plans/`，简单改动直接传清晰目标与契约。
- **多路真并发 + 精简施工图**：**仅当任务天然包含 2 个及以上接口边界清晰、彼此低耦合的独立模块**（如后端 API 与前端页面、或两个独立子系统）时才拆 2～3 路并发，**每轨自带本层单测（严禁把单测单拆成一条隔离轨）**；动工前写定稿施工图 `<projectRoot>/.agent-tower/plans/YYYY-MM-DD-<slug>.md` 并登记同目录 `INDEX.md`，施工图只写边界、接口契约与 Checklist，禁写百行逐字 DOM/CSS 说明书。

## 2. 定稿施工图（`.agent-tower/plans/*.md`）四要素与三禁

### 必备四要素
1. **已拍板业务边界与不变量**：写清用户已确认的默认行为、数据存储位置、错误码与向后兼容底线。
2. **分轨写文件互斥矩阵（Track Matrix）**：
   - 逐轨列出独占可写文件集合（`targetPaths`）与只读参考导航路径（`readPaths`）。
   - **硬约束：不同并发轨的可写文件集合必须 100% 互斥**。若存在共享组合根（如 `core/orchestrator.mjs`、`index.html` 或导出表），要么由主会话在派工前先落好最小挂载桩，要么留到合入收口步统一接线。
3. **跨轨接口契约**：明确约定前后端 RPC 名称、请求/响应字段、事件广播名与 DOM 钩子 ID，确保各轨在隔离工作树中盲写也能一次对接通过。
4. **可勾选验收 Checklist（`- [ ]`）**：每条对应可验证的行为、异常/边界分支及关联定向单测名（终审官收到 `planPath` 时将自动逐条对照 `[ ]` 清单核验）。

### 严格三禁
- **禁写伪代码长信**：只给目标、文件边界与接口契约，不替执行官手写大段函数实现。
- **禁超前过度设计**：遵守路线图隔离，严禁夹带用户未要求的防御性白名单、未来钩子或多余抽象层。
- **禁把 `.agent-tower/spec/**` 或 `.agent-tower/spec-archive/**` 列入执行官写目标**：项目规范修改只走专职 `curator` 只读提案与面板确认闭环。

## 3. 并行派工与 `planPath` 去重投递

1. **外部 CLI 多轨并派**：通过单次 `delegate_parallel_batch` 并发提交各轨任务，每项显式传入：
   - `presetKey`（从本项目当前模式 `enabledKeys` 按点名 → `★` 首选（单兵默认选 `★`；多路并派主力轨必含 `★`，其余并发轨再按专长/空闲复用补位）挑选）；
   - `isolation: "worktree"`（多路写改必开独立 Git Worktree 防互相覆盖）；
   - `planPath: ".agent-tower/plans/YYYY-MM-DD-<slug>.md"`（编排器自动包装 `<agent_tower_plan>` 并在同会话续聊时按哈希去重，`24 KiB` 内联预算）；
   - 本轨专属 `targetPaths`（自动触发关联 `tests:` 快测提示与演进索引过滤）及只读 `readPaths`。
2. **宿主原生混合拆轨**：多路拆单时严禁为图外部 `worktree_integrate` 合入省事而绕开已标 `★` 的宿主原生成员（原生成员正常通过同一轮派发生成票据并并行执行返回的 `hostActions` + `workspace: "share"` 混编拆轨，在 `brief` 指明本轨负责章节与文件互斥范围）。

## 4. 合入核验、定向快测与终审收口

1. **逐轨核 Diff 后合入**：各路完工后，主会话先调 `worktree_diff` 检查是否越界修改他轨文件、误改 `.agent-tower/spec/**` 或遗留临时文件；核验无误后调 `worktree_integrate` 合入主目录并清理对应工作树（自动保护主目录未提交用户改动）。
2. **中途只跑快检与关联单测**：合入接线后立即运行项目语法快检与关联定向单测（优先复用既有测试夹具，禁新建一次性重型服务或无头浏览器脚本；全量回归留到正式发版前跑 1 次）。
3. **对照 Checklist 终审**：在开启 `reviewer` 阶段时调用 `review_code`，传入同一 `planPath` 与完整 `targetPaths`（默认异步返回 `taskId`，随后经 `task_status` 等待结算）。终审官按 `review_and_fix` 对照 Checklist 审改一体并自测通过后，主会话更新 `.agent-tower/plans/INDEX.md` 完成状态并向用户做自然融合白话汇报。
